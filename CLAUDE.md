# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## About This Project

Personal site for Chris Wallace (designer and founder, now building Homebase Assistant). The public site is a single standalone page, `index.html`, served through Jekyll 4.3. The Tailwind CSS v3 and GSAP pipeline described below belongs to the previous multi-page site and is no longer used by the page.

## Development Commands

```bash
# Full dev server (Jekyll + CSS watch + browser-sync in parallel)
npm start

# Individual tasks
npm run jekyll:serve    # Jekyll only (incremental, watch mode)
npm run css:build       # Build Tailwind CSS (all entry points)
npm run css:watch       # Watch CSS changes with nodemon
npm run js:minify       # Concatenate and minify JS (runs build-minify.js)

# Production build
npm run jekyll:build    # JS minify → Jekyll build → CSS minify
```

## Architecture

### CSS Pipeline

Tailwind processes multiple entry point CSS files into root-level output files:

| Source | Output |
|--------|--------|
| `assets/css/main.css` | `assets/main.css` |
| `assets/css/legendary.css` | `assets/legendary.css` |
| `assets/css/interactive.css` | `assets/interactive.css` |
| `assets/css/content-preloader.css` | `assets/content-preloader.css` |

`assets/css/main.css` imports component CSS files and uses CSS layers (`reset, base, tokens, components, utilities, overrides`). Design tokens (CSS custom properties) live in `assets/css/tokens.css`. Tailwind config is in `tailwind.config.js` with fluid-tailwind for responsive clamps and a custom color system.

### JavaScript Pipeline

`build-minify.js` uses terser to:
- Concatenate `navigation.js`, `homepage.js`, `video-player.js`, `animations.js`, `card-flip.js`, `simple-card.js`, `image-lazyloader.js`, `zoomable.js` → `assets/js/concatenated.min.js`
- Minify individual files: `fxhash.js`, `interplay-page.js`, `toc-toggle.js`

In production (`jekyll.environment == 'production'`), `_includes/scripts.md` loads only `concatenated.min.js`. In development, individual source files are loaded. This conditional is set in `_includes/scripts.md`.

A standalone page (inline CSS, JS and font, no front matter; the 3D Woodie viewer is the one script it loads from a file), so Jekyll copies it as-is and the layouts, includes and asset pipeline below are not used by it. Each `.seg` section holds a fixed `.panel` with one or more `.say` lines that share one place: scroll position shows one line at a time, lights its words (a block cursor follows the last lit word), and reshapes the outlined frame drawn on the `#frame` canvas. Chapter ticks (`.ticks`) run down the right edge, just inside the frame: one tick per chapter, each a link to the section the chapter starts at. The current chapter's tick is longer, and its name shows for a moment when you reach it. A click jumps to that section's first rest point, and a press and drag along the ticks jumps to each chapter the pointer passes and names it. On a touch screen the ticks wait folded into one short line under the contact link (`.ticks-handle`), with a dot for the current chapter, and the chapter's name flashes beside it when you reach one. A tap on the line opens the ticks in their place (`.is-open`), naming the current chapter; a press on it and a drag down into them moves between chapters. They fold again after a jump, a tap elsewhere, Escape, or 4 seconds unused. The page sits on one grid: a side margin (`--gutter`, 28px on a phone, up to 88px) and, from 900px, twelve columns inside it (`--col-gap`). Words start at column 1 (columns 1 to 6 in a story panel, 1 to 5 from 1280px). Every frame, plate and the Interplay piece start at column 7 (`target()`, `artScroll`), which is also where the projects' second column starts; a frame as wide as its stage ends at the right margin, under the contact link. A frame that is limited by height keeps its left edge on the line and leaves the room to its right. On a narrow screen the frames start at the side margin, where the words start. Frames and the piece leave room for the chapter navigation (`navRoom`): they end 12px before the tick marks where the ticks sit inside the margin, and on a touch screen a frame that would reach the folded handle starts below it. Keep new work on these lines. The type sizes (`--display-size`, `--impact-size`, `--say-size`) grow steadily with the screen and meet at 900px. Behind the blue sections is the sky (`#sky`, the `sky` object in the page script): slow clouds in tones of the page's own blue, drawn by a WebGL fragment shader on a coarse grid of square cells (about 3 CSS px, a whole number of screen pixels) and scaled up without smoothing. The shader draws on a canvas that is never on the page, and each picture is copied to the 2D canvas inside `#sky`: a WebGL canvas on the page itself lost a strip of sky above a film plate, so keep it off the page. On a touch screen the sky and the other page colours (`#dark`, `#grove`, `#slate`, `#paper`, `#sheet`) run on past the top and the bottom of the screen (`--over-top`, `--over-foot`), because a phone's browser bars float over the page and some browsers show the page behind them: what shows there should be sky, not a flat band. Nothing is laid out out there, and the shader measures from the top of the screen (`uTop`, `uView`), not the top of its canvas. The page is also fitted again when the visual viewport changes size, which is how a phone reports its bars folding away. X's own browser inside its iPhone app lays the page out under its bar at the foot of the screen (the close key, the address and the post's actions) without telling the page, so where the user agent says `Twitter` on an iPhone or iPad the root gets `.in-x`, which sets `--foot` (92px, `0px` elsewhere): the panels and the close add it to their bottom padding, and the script reads it (`foot`) so a full-page drawing's frame, the question marks and the film over the page keep clear of it too. The page's own background follows the colour on screen too (`tintPage()`, called from `draw()`): the blue, or the night, forest, slate or paper mixed in as those layers fade, set on `html`, on `body` and in the `theme-color` meta. The layers cover it, so nothing of the page shows it; it is there because a phone's browser colours its own bars from it. A new page colour needs adding to `PAGE` and to the list in `tintPage`. Two decks of noise drift on their own and move up a little with the scroll; each cell lands on a ladder of six blues (a deeper blue, `--signal`, then four steps toward `--ink-soft`) through a 4×4 ordered dither. The bright clouds thin out as they near whatever is read: `measure()` hands `sky.set` up to six rectangles (the words, the frame, the project cards or the close, the ticks, the name, the contact link), and each one only raises the bar a bright cloud has to clear, falling away gently with distance, so the clouds draw back along their own edges. The haze and the deeper patches of sky (the three quietest tones) carry on behind the words unchanged. Keep it that way: never clear a patch of flat blue behind text, because it shows as a block; text and line work sit in the same sky as everything else, on its quiet tones. A state whose drawing runs over the whole page holds all the clouds low so its lines read. While the sky is on, a chapter's name (`.tick-name`) has a soft halo of the page's blue in place of its flat blue chip. The other page colours (`#dark`, `#grove`, `#slate`, `#paper`) sit over the sky and cover it, and it stops drawing while they do or while the tab is hidden. It draws 15 times a second, and on every frame while the page scrolls; reduced motion holds the clouds still. It times its first pictures, and where one takes more than a few milliseconds (a browser drawing WebGL on the processor) it holds the clouds still too and redraws at most four times a second, only when the words change. ### Cache Busting

The `version` field in `_config.yml` is appended as a query param (`?v={{ site.version }}`) to CSS and JS `<link>`/`<script>` tags. Bump this when deploying changes that require cache invalidation.
